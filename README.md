# suchnost_bot

Telegram-бот регистрации и модерации постов на aiogram с PostgreSQL в Neon.

## Установка и подключение

```bash
cd /Users/draxc/suchnost_bot
uv pip install --python .venv/bin/python -r requirements.txt
```

В Neon открой проект → **Connect**, выбери нужную базу и скопируй строку
подключения PostgreSQL. Вставь её в `DATABASE_URL` в локальном `.env` рядом
с ботом. Сохрани параметры `sslmode=require` и `channel_binding=require`,
если они указаны в строке Neon. Драйвер psycopg принимает эту строку напрямую.

В `.env` нужны три настройки:

```dotenv
TEST_TOKEN=your_telegram_bot_token
CHANNEL_ID=your_channel_id_or_username
DATABASE_URL=postgresql://user:password@your-endpoint.neon.tech/neondb?sslmode=require&channel_binding=require
```

Образец: `.env_example`. Секреты из `.env` исключены из Git.

## Создание таблиц и запуск

Чтобы создать таблицы и проверить соединение без запуска Telegram-бота:

```bash
.venv/bin/python database.py
```

При запуске бота таблицы также создаются автоматически:

```bash
.venv/bin/python reg_bot.py
```

При запуске бот отключает webhook перед polling. Ожидающие сообщения при этом
сохраняются (`drop_pending_updates=False`).

В PyCharm выбери интерпретатор `/Users/draxc/suchnost_bot/.venv/bin/python`
и запускай `reg_bot.py`.

Файл `schema.sql` создаёт таблицы `users`, `admins`, `owners`, `posts`.
Telegram ID хранятся в `BIGINT`. Запросы выполняются асинхронно через пул
из 1–5 соединений. Пул закрывается при завершении бота.

Данные из SQLite не переносятся. Старый `bot.db` сохранён, но код его больше
не использует. Логи рассылок и действий администраторов остаются в `logs.csv`
и `admin_logs.csv` в папке проекта.

## Первый владелец и администратор

Новые таблицы пустые. После их создания выполни в **SQL Editor** Neon,
заменив `123456789` на свой числовой Telegram ID:

```sql
INSERT INTO owners (telegram_id) VALUES (123456789)
ON CONFLICT (telegram_id) DO NOTHING;

INSERT INTO admins (telegram_id) VALUES (123456789)
ON CONFLICT (telegram_id) DO NOTHING;
```

Владелец может выполнять `/add_admin` и `/remove_admin`. Администратор может
модерировать посты, смотреть пользователей и делать рассылки.

## Отправка и модерация

При любом сообщении, команде или нажатии кнопки пользователь автоматически
добавляется в `users`. Имя и username обновляются при следующих обращениях.
Команда `/start` показывает персональное приветствие с заголовком, цитатой,
короткой инструкцией и кнопкой **Предложить пост**; предварительно вводить её не нужно.
Автоматическая регистрация не выдаёт права администратора или владельца.

Чтобы предложить пост, отправь обычный текст или фото с подписью либо без неё.
Команда `/send` больше не нужна. Команды обрабатываются отдельно и не становятся
постами; неизвестная команда показывает подсказку.

Каждый администратор получает пост с двумя кнопками: **Принять** и **Отклонить**.
При принятии пост публикуется в канале, при отклонении публикации нет. Автор
получает уведомление о решении. Команды `/accept` и `/reject` заменены кнопками.

Внизу публикации в канале через пустую строку добавляется ссылка **Предложка**,
которая открывает этого бота. Ссылка добавляется и к тексту, и к подписи фото.
Если полная подпись с ссылкой не помещается в лимит Telegram, текст со ссылкой
отправляется сразу после фото. Длинный текст делится без обрезки содержимого.

После решения кнопки у нажавшего администратора убираются. Если другой администратор
нажмёт кнопку на старой копии, бот сообщит о принятом решении. Блокировка строки
в PostgreSQL не позволяет двум администраторам одновременно обработать один пост.
Если публикация не удалась, пост остаётся в ожидании, и попытку можно повторить.

## Просмотр постов администратором

- `/posts 10` — последние 10 постов; вместо 10 укажи нужное положительное число.
- `/all_posts` — все посты, начиная с самых новых.

Обе команды показываются в `/admin` и доступны только администраторам. В историю
входят все посты: ожидающие решения, принятые и отклонённые. Каждая запись
приходит отдельным сообщением в формате:

```text
id: 123
username: @username
id_account: 123456789
name: Имя автора
text: Текст поста
photo: Telegram file_id или -
```

В каждом новом посте сохраняются Telegram ID автора (`user_id`), его username
(`author_username`) и полное имя Telegram (`author_name`) на момент отправки.
История показывает эти сохранённые данные, даже если профиль позже изменится.
При отсутствии username показывается `-`. Для старых постов при обновлении схемы
подставляются доступные текущие данные из `users`; прежние имена восстановить нельзя.
При наличии фото оно прикладывается к сообщению.
Если полная запись превышает лимит сообщения или подписи фото, она приходит
одним `.txt`-файлом без обрезки текста. История загружается из PostgreSQL порциями,
а при ограничении частоты отправки бот ждёт и продолжает выдачу.

## Проверка кода

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Эти тесты проверяют автоматическую регистрацию, маршрутизацию команд, отправку
постов и клавиатуру через диспетчер aiogram с подставным слоем базы. Они
не подключаются к Neon и не отправляют сообщения в Telegram.

Для проверки сценариев на настоящей базе из `.env`:

```bash
RUN_POSTGRES_TESTS=1 .venv/bin/python -m unittest discover -s tests -v
```

Этот вариант создаёт таблицы, если их ещё нет, выполняет сценарии с тестовыми
пользователями в транзакции и откатывает тестовые записи. Счётчики ID могут
увеличиться. Отправка в Telegram и запись CSV-логов подменены в тесте.

Документация: [подключение к Neon](https://neon.com/docs/connect/connect-from-any-app),
[асинхронный пул psycopg](https://www.psycopg.org/psycopg3/docs/advanced/pool.html).
